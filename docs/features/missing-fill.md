# 缺集补漏

缺集补漏分两步：先拿 TMDB 的已播集数和 Emby 里已有的集数做对比，再从 HDHive 或 Telegram 找资源并转存到 115。它不会替 Emby 刮削，也不会自动生成 STRM；原来的入库流程仍要正常工作。

::: info 版本要求
缺集补漏和 Telegram 资源搜索属于**专业版**功能。没有专业版授权时，侧边栏不会显示“补漏”菜单。
:::

::: important 开启前先确认
- Emby 实例能连接，剧集已经正确匹配 TMDB ID
- 系统配置里已经填写 TMDB API Key
- 至少有一个可用的内置 115 账号，并设置好转存目录
- HDHive 和 Telegram 至少准备一个资源来源

第一次先用“扫描缺集”核对结果，确认季集识别正确后再用“扫描并补齐”。
:::

## 先看懂两个按钮

:::: card-grid
::: card title="扫描缺集" icon="material-symbols:search"
只检查并记录缺少哪些集，不搜索资源、不解锁、不转存。第一次配置时先点它，风险最低。
:::
::: card title="扫描并补齐" icon="material-symbols:playlist-add-check"
先扫描缺集，然后按 HDHive / Telegram 来源找资源并自动转存。HDHive 资源可能消耗积分，也会实际操作 115 文件。
:::
::::

任务在后台运行，关闭页面不会停止。进度和失败原因到 **补漏 → 补漏历史** 查看；需要中止时点击当前任务旁的“停止”。

## 第一次配置

::::: steps

1. **选择实例和媒体库**

   进入 **补漏 → 缺集扫描**，选择 Emby 实例，展开“高级扫描条件”，点击“从 Emby 拉取”。**一次建议只选 1～2 个媒体库**，任务更稳定，也方便查看是哪一个库出了问题。

2. **设置扫描范围**

   “扫描上限”和“补齐上限”建议填写相同数值。小型媒体库填 `1000`，内容较多时填 `2000`～`3000`。

3. **选择资源来源**

   HDHive 已授权就打开“HDHive 来源”。使用 Telegram 前，必须先按下文建立 Telegram 资源索引，否则打开开关时系统会提示没有可用频道。

4. **设置 115 目标**

   明确选择一个内置 115 账号和单独的补漏目录。转存模式推荐选“全部转存”，对目录结构复杂、整季打包的分享更省心。

5. **先扫描，再补齐**

   点“扫描缺集”，到补漏历史核对结果。确认没有把未播、特别篇或命名错误识别成缺集后，再点“扫描并补齐”。

6. **最后开启定时扫描**

   手动跑通后再开启，推荐 Cron `30 4 * * *`，即每天凌晨 4:30。

:::::

## Telegram 搜索怎么配置

Telegram 补漏不是临时去频道里搜索，而是先把指定聊天的资源消息同步到 ResourceTool 本地数据库，再从本地索引中匹配。**Telegram 搜索、求片自动找片和缺集补漏共用同一份索引。**

### 前置条件

1. 在 **概览 → 插件库 → Telegram 助手** 登录 MTProto Session
2. Session 使用的个人账号已经加入目标频道、群组或私密聊天
3. 进入 **补漏 → Telegram 搜索**，点击右上角“Telegram 配置”

Bot Token 不能代替 MTProto Session。Bot 看不到自己无权访问的频道历史消息。

### 添加资源来源

1. 点击“新增来源”
2. 搜索频道名称、`@用户名` 或 Chat ID
3. 选择一个或多个来源并保存
4. 保持来源为启用状态
5. 先点“立即同步”，再用一个确定存在的片名试搜

支持公开频道、私密频道、群组、用户和 Bot。私密来源能否读取，取决于 Session 账号本身是否有访问权限。

### 三种索引操作

| 操作 | 做什么 | 什么时候用 |
|---|---|---|
| **立即同步** | 拉取最新消息，速度较快 | 日常刷新、新增来源后先测试 |
| **补全历史** | 从当前断点继续向更早消息同步 | 想搜索频道以前发布的资源 |
| **重建缓存** | 清掉该来源已有索引，从最新消息重新扫描到历史尽头 | 索引明显错乱或解析规则升级后 |

::: warning 历史同步可能很久
大频道补全历史会遇到 Telegram 限流。系统会冷却并保存断点，之后可以继续，不要反复删除来源或重复重建。
:::

### 来源权重怎么设

权重是搜索评分的额外加分，不是同步频率。默认 `100` 通常够用：

- 内容规范、季集标注准确的频道：`120`～`150`
- 普通资源频道：保持 `100`
- 标题混乱、广告较多的来源：`50`～`80`

拖拽顺序决定同步先后和同分时的排序。不要为了让某个频道排第一就填特别大的权重，否则错误资源也会被放大。

### 匹配阈值怎么调

缺集扫描页的“Telegram 匹配阈值”默认 `300`。分数越高要求越严格：

| 情况 | 调整建议 |
|---|---|
| 经常匹配到同名但不同年份、不同季 | 提高到 `350`～`450` |
| 手动搜索有正确资源，但自动补漏总说未命中 | 先降到 `250` 观察 |
| 频道标题没有年份或季集写法不规范 | 不要盲目降分，优先降低该来源权重或换来源 |

先在 **Telegram 搜索** 页面搜索片名，结果卡片会显示总评分和各项加分原因。确认正确资源的常见分数后，再调整自动补漏阈值。

### 搜索结果如何转存

在 Telegram 搜索结果点击“预览转存”，系统会解析消息中的 115、magnet、ed2k 等链接。手动搜索适合验证消息能否正确解析；缺集补漏则会继续按季、集和阈值筛选，并使用缺集扫描页设置的目标 115 账号与目录。

## 转存模式

| 模式 | 行为 | 推荐场景 |
|---|---|---|
| **全部转存** | 接收整份分享根内容 | **推荐**，兼容整季和复杂目录，成功率更高 |
| **缺集转存** | 尽量只接收命中的缺集 file_id | 只想精确转存单集，并且资源目录很规范 |

一般直接使用“全部转存”。它可能同时带入已有集，但对整季打包和多层目录更稳；非常在意重复文件时再尝试“缺集转存”。

## 推荐设置

::: tip 直接照着设置
- 每次选择 **1～2 个媒体库**
- 扫描上限和补齐上限填写相同数值：建议 `1000`～`3000`
- HDHive、Telegram 来源：配置正常就开启
- 转存模式：**全部转存**
- 目标账号和目录：明确选择，不使用默认账号
- 群通知：开服用户开启，个人使用可以关闭
- 定时扫描：先关闭，手动跑通后再开启
- 执行 Cron：`30 4 * * *`，每天凌晨 4:30
- “高级运行参数”中的其他项目：**全部保持默认值**
:::

只有日志明确提示超时、限流或匹配错误时，才需要调整高级参数。正常情况下不要修改并发、QPS、等待时间和 115 预览间隔。

## 跳过白名单

跳过规则用于处理“不希望系统补”的内容，例如未播剧集、特别篇、合集或手工维护的剧。

| 匹配方式 | 适合情况 |
|---|---|
| **名称** | 快速跳过某个标题，但同名作品可能一起命中 |
| **TMDB ID** | 最稳定，推荐用于长期规则 |
| **Emby ID** | 只针对当前 Emby 中的具体条目 |

季和集填 `0` 表示不限。只想跳过第二季，就填季 `2`、集 `0`；只跳过 S02E05，就同时填 `2` 和 `5`。

## 常见问题

::: details Telegram 来源开关无法保存
先到 **补漏 → Telegram 搜索 → Telegram 配置** 添加并启用至少一个来源。还要确认 MTProto Session 在线，且 Session 账号能打开该聊天。
:::

::: details Telegram 手动搜索没有结果
先看来源的缓存状态。新来源只做“立即同步”通常只有最新消息；需要旧资源时点“补全历史”。也可以换一个确定出现在近期消息里的完整片名测试。
:::

::: details 手动搜索有结果，自动补漏却未命中
核对年份、季号、集号和评分明细。正确结果低于阈值时可小幅降低阈值；如果候选本身标题不规范，优先调整来源权重，不要直接把阈值降得很低。
:::

::: details 扫描到了缺集，但没有自动补上
“扫描缺集”本来就不会转存；需要点击“扫描并补齐”。如果已经使用后者，到补漏历史查看是没有候选、积分限制、Cookie 失效、目录无效还是转存失败。
:::

::: details 文件转存成功，但 Emby 里还是缺集
ResourceTool 只负责把资源放进 115。确认 STRM 生成、媒体库同步和 Emby 扫描流程正常，然后让 Emby 重新扫描对应媒体库。
:::

## 2.1.1 相关改进

- 115 分享内容很多时会继续翻页，不再只处理第一页
- 已接收或已转存时，会通过临时目录更稳妥地兜底
- 支持直接选择 115 根目录
- 执行前检查目录是否仍可访问、是否属于当前账号
- 扫描并补齐前会先保存页面上的最新策略

旧配置不需要手工迁移。若升级后提示目录失效，重新打开目录选择器选择一次即可。
